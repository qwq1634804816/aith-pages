Clawd Code：Python open-source porting code replicating the leaked version of Claude Code

github.com/instructkr/clawd-code

Clawd Code is an independent and open-source Python project aimed at replicating the core interactions and tool scheduling mechanisms of the leaked Claude Code.

Clawd Code is an independent project aimed at porting the leaked AI programming assistant Claude Code to Python. Originally developed by the creator based on the oh-my-codex (OmX) framework, it focuses on ‘Harness Engineering’ (agent scheduling engineering), exploring how AI systems can efficiently schedule external tools, orchestrate complex tasks, and manage long-running contexts. This tool is not merely a backup of the codebase or a proof of concept, but a true automation programming assistant that can ‘get real work done.’ By running locally, it can autonomously read the file system, execute code, run tests, and provide various advanced collaboration modes, allowing developers to deeply understand the working principles and underlying designs of the next generation of automated AI development agents.

Feature List

  • Replicating the native terminal experience of Claude Code: Interact with large language models in the terminal environment, allowing AI to autonomously browse directories, read code files, write and modify code, and trigger local tests based on natural language instructions.
  • Parallel Code Review ($team mode): A unique multithreading mode that supports launching multiple AI instances to deeply review the codebase simultaneously, ensuring comprehensive code quality validation and security review.
  • Architectural-level Persistent Execution ($ralph mode): Supports continuous execution loops, allowing AI to logically reason, generate code, and perform multiple validations from an ‘architect’ perspective, ensuring tasks completely meet requirements.
  • OmX underlying workflow engine support: Uses oh-my-codex layout flow orchestration to provide flexible underlying scheduling logic, ensuring large language models do not easily lose context in complex tasks.
  • Flexible external toolchain integration: By configuring environment variables or tokens, agents can directly call third-party tools like GitHub and Linear, achieving automated workflows.
  • Custom workspace and agent identity management: Manage agent commands and memory context using Markdown text files, allowing users to edit local text at any time to change the AI’s personality, coding standards, and workflow habits.

Usage Help

Welcome to use Clawd Code. This tool is a terminal AI programming assistant built on the leaked version of Claude Code, capable of automating coding, reviewing, and testing tasks. To ensure full utilization of the tool’s potential and achieve optimal efficiency, please read the installation and operation guide carefully.

I. Installation and Pre-Environment Preparation

1. System and Environment Requirements

  • Operating System: Supports macOS, Linux, and Windows (WSL2 is recommended for optimal terminal compatibility).
  • Python Version: Python 3.10 or higher is required.
  • Package Management Tool: It is recommended to use pip. To avoid dependency conflicts, it’s best to create an isolated Python virtual environment using virtualenv or conda.

2. Obtaining the Source Code and Installing Dependencies
Open the command line terminal and execute the following commands to clone the Clawd Code project locally and install the necessary dependencies:

# Clone the open-source repository locally
git clone https://github.com/instructkr/clawd-code.git
cd clawd-code
# Create and activate the Python virtual environment (recommended)
python3 -m venv venv
source venv/bin/activate  # Windows users should use venv\Scripts\activate
# Install the core dependencies of the project
pip install -r requirements.txt

3. Environment Variables and API Key Configuration
Clawd Code is based on a large language model agent system and requires configuring the model API key to give it thinking and coding capabilities. A basic environment variable template file env.example is provided in the project root directory.

cp .env.example .env

Use a text editor (like vim, nano, or VS Code) to open the newly created env file and fill in your API Key:

# Required: Configure the API key for [Anthropic](https://www.kdjingpai.com/en/claudeanquanfubai/) (recommended to use Claude 3.5 Sonnet)
ANTHROPIC_API_KEY="sk-ant-api03-xxxxxxxxxxxxxxxxxxxx"
# Optional: If you want the agent to execute the GitHub automation submission process, it is recommended to configure the Personal Access [Token](https://www.kdjingpai.com/en/tokenization/)
GITHUB_ACCESS_TOKEN="ghp_xxxxxxxxxxxxxxxxxxxxxxxxxx"

II. Core Functions and Basic Operation Workflow

1. Start and Enter Agent Interaction Mode
After ensuring the environment variable configuration is correct and the virtual environment is activated, start the agent’s main program with the following command:

python main.py

Once started, the terminal enters an interactive command prompt interface. At this point, Clawd Code takes over the context of the current directory. You can directly issue development tasks in natural language.
Basic operation example:
👤 User: “Please analyze the src/utils.py file in the current directory, find functions that might cause memory leaks, and provide refactoring suggestions.”
🤖 Agent: (Clawd Code starts scheduling the local file reading tool -> analyzes the code content -> outputs the analysis report -> asks if you need it to directly modify the file)

2. Using $team Mode: Parallel Code Review
In large Pull Requests or refactorings involving multiple modules, single-threaded AI might miss things; in such cases, you can invoke Clawd Code’s $team mode.
Operation method: In the terminal interactive mode, input a command prefixed with $team:

$team Review all modifications in the current Git branch, focusing on checking for SQL injection vulnerabilities and multithreaded safety issues.

Working Principle: The OmX scheduling engine dispatches multiple independently evaluated AI instances (such as network security, runtime performance, code specifications), reading code in parallel, and then consolidating review opinions, significantly enhancing the rigor and efficiency of Code Review.

3. Using $ralph Mode: Architectural-level Persistent Validation Execution
Common code generation tools usually just “write code once” and cannot guarantee that “these codes will work smoothly within the overall architecture.” The $ralph mode is a high-level feature designed for this, granting AI persistent loop execution and multi-step trial-and-error validation permissions.
Operation method:

$ralph Migrate the project's underlying SQLite operations to PostgreSQL, please modify the code, write unit tests, and run validations until the tests pass.

Working Principle: Once started, Clawd Code enters an automatic closed loop of “thinking -> planning -> coding -> running tests -> catching errors -> self-correcting -> retesting.” You can observe the process and status logs, and manually intervene or terminate at any time by pressing Ctrl+C, making it very suitable for handling system-level refactoring tasks.

III. Advanced Configuration: Customizing Workspace and External Tool Integration

1. Managing Agent Memory and Workspace (.workspace)
When running Clawd Code for the first time, a hidden configuration folder similar to .clawd-workspace/ will be automatically generated in the project directory, storing several Markdown format configuration files:

  • identity.md: Defines the agent’s role and personality. For example, you can change it to “You are a Linux kernel developer with very high standards for code.”
  • rules.md: Sets the coding standards for the project, such as “All Python functions in this project must use Type Hints, no global variables, and must have Docstring.” You can modify these local Markdown files through a text editor to customize an exclusive AI assistant that aligns with team habits.

2. External Tool Scheduling Configuration (Tools & Integrations)
The power of Clawd Code lies in its ability to extend the ‘toolchain.’ By configuring specific tokens, the agent can directly operate third-party tools:

  • Integrating GitHub Pipeline: By configuring GITHUB_ACCESS_TOKEN in the config file, the terminal can execute commits and create PRs directly. Clawd Code will automatically invoke Git commands and the GitHub API to complete operations.
  • Calling Local CLI Tools: If your system has formatting or static analysis tools installed (like black, mypy, or ruff), you can directly command the AI: “After finishing code modifications, please format all modified files.” The AI will execute corresponding commands and clean up the code, just like a real programmer.

IV. Precautions and Best Practices

  1. Security and Permission Isolation: Clawd Code has permission to read, write, and even delete local files, so it is recommended to use Docker or dedicated sandbox VMs to avoid unintended deletions or overwrites of important files when executing unknown source automated tasks or those involving core production data.
  2. Token Costs and Monitoring: Frequently using $team and $ralph modes will generate a large number of API requests. It is advisable to first let the AI output a simple execution plan for complex tasks, confirm the logic is correct, and then execute it.
  3. Academic Research and Secondary Development: This project aims to allow developers to transparently understand the principles of tool scheduling for large models. It is recommended to carefully read the underlying source code to learn how Clawd Code interprets model outputs and converts them into local Python functions.

Application Scenarios

  1. Local Automated Programming and Code Refactoring: When handling legacy codebases, developers can use Clawd Code to automatically analyze complex function dependencies and directly apply refactoring patches in the local environment, simplifying the operation process.
  2. Multidimensional Parallel Review of Codebase: When merging code into the main branch, using $team mode for quick automated checks of the codebase, Clawd Code provides review opinions from multiple perspectives including network security, execution performance, and code standards, enhancing review efficiency.
  3. Agent Architecture Research and Secondary Development: Provides a clean architectural reference source code for AI Agent developers, helping them learn how to build task persistence queues in Python to intercept and process model outputs.
  4. Closed-loop Fixing of Complex Issues (Bug Fixing): Use $ralph mode to let Clawd Code autonomously analyze error logs, correct business logic, and repeatedly run local tests until no exceptions occur.

Q&A

  1. What is the relationship between this project and the original Claude Code?
    Clawd Code is an independent open-source Python reimplementation based on the leaked version of Claude Code, accurately replicating its core tool scheduling and terminal agent mechanisms.
  2. Why conduct a Python open-source port?
    This tool is primarily for educational purposes. The original Claude Code code is closed-source and complex in structure, while this open-source version removes the commercial parts to provide developers with transparent learning materials.
  3. What model does Clawd Code need to support?
    The OmX scheduling framework requires a large language model with strong logical reasoning and native tool-calling capabilities. It is recommended to configure Claude 3.5 Sonnet / Opus or OpenAI’s GPT-4o.
  4. Can the project be used for commercial development?
    Although this project is open-source, the developer clearly indicates it is mainly for learning. When privately integrating into commercial workflows, one must assume potential costs and security responsibilities and it is recommended to run it in a sandbox or container to ensure file security.
